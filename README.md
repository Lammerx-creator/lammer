# Deutsch B2 Beruf Trainer · браузерная версия

React + TypeScript. PDF, словарь и прогресс сохраняются **на вашем устройстве в IndexedDB**. Сервер, VPS, регистрация и платные API не нужны. Эта версия предназначена для GitHub Pages; серверная SQLite заменена браузерной базой по согласованию с пользователем.

Адрес публикации: **https://lammerx-creator.github.io/lammer/**.

## Как начать

1. Откройте сайт на компьютере или телефоне и выберите **B2 Beruf · PDF → Материалы**.
2. Выберите «Без ответов» и загрузите `Без ответов Alle Information от 21.09.26.pdf`.
3. Выберите «С ответами» и загрузите `Alle Information от 21.09.26.pdf`.
4. Откройте словарь, найдите `Rechnung`, проверьте контексты и перевод. Затем перейдите в практику: карточки, пропуски, перевод или восстановление фрагмента.
5. Регулярно сохраняйте **Прогресс → Экспорт JSON**. Для переноса сначала загрузите те же PDF на другом устройстве, затем импортируйте прогресс.

**Сами PDF не опубликованы вместе с сайтом.** Их нужно один раз импортировать в каждом браузере. Это сохраняет документы приватными. Файлы не отправляются на сервер, переводчик или CDN. Загружается только код сайта и PDF.js с того же адреса GitHub Pages. Распознавание речи, если вы включите его, может использовать отдельный сервис браузера.

Прогресс на телефоне и компьютере автоматически не синхронизируется. Приватный режим, очистка данных сайта и автоматическое освобождение места браузером могут удалить библиотеку. Сохраняйте исходные PDF и резервные копии.

## Разработка и проверки

Нужны Node.js 24+ и npm:

```sh
cd /workspace/lammer
npm ci
npm run dev
```

Vite выводит адрес приложения в терминале. Backend запускать не требуется. Используйте существующую рабочую копию: облачная задача уже изолирована, дополнительный Git worktree не нужен.

```sh
npm test                  # модули браузерной версии и существующих занятий
npm run typecheck
npm run build             # обычная сборка с базовым путём /
npm run preview           # локальная проверка production и PWA
```

Проверка пути GitHub Pages и реального браузерного PDF-импорта:

```sh
npx playwright install chromium
npm run test:e2e
```

Если Chromium уже установлен в системе, можно указать его путь:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

Playwright сам собирает версию с `/lammer/`, запускает статический preview и проверяет компьютерный и мобильный интерфейс. Он импортирует настоящий двухстраничный PDF через PDF.js, проверяет дедупликацию, источники, карточки, сохранение после перезагрузки, JSON-экспорт, открытие PDF из IndexedDB и **офлайн-импорт без API/CDN**. Приватные пользовательские PDF в тестовые файлы не включены. Оба исходных 209-страничных PDF отдельно проверены в браузере в облачной среде.

## Публикация на GitHub Pages

Pages для репозитория должен использовать ветку `gh-pages`, каталог `/ (root)`.

```sh
npm ci
npm test
npm run build -- --base=/lammer/
npm run publish:pages
```

`publish:pages` требует права Git push, использует текущий origin и сохраняет историю `gh-pages`. Он публикует **только `dist/`**, добавляет `.nojekyll` и сохраняет существующий `CNAME`. PDF, SQLite, `.env` и личный прогресс не входят в сборку. Команда не создаёт и не оплачивает хостинг. Если Pages ещё не включён, его нужно один раз включить в настройках GitHub. После push дождитесь сборки Pages и проверьте `release.json` на сайте: сам Git push ещё не доказывает обновление внешнего адреса.

## Словарь и качество извлечения

PDF.js работает локально в Web Worker. Сохраняются оригинальный PDF, текст каждой страницы, номер страницы, предполагаемый раздел, исходные словоформы и контексты. Лимиты MVP: 20 МБ и 1000 страниц на PDF. Для зашифрованного файла нужна незашифрованная копия; OCR сканов не включён.

Раздел определяется эвристически по заголовку в начале страницы и наследуется до следующего заголовка. Это предварительная разметка: смешанные страницы и нетипичная вёрстка могут требовать проверки. Сложность — редактируемая метка, не автоматическая оценка CEFR.

Дедупликация использует SHA-256 нормализованного текста фрагмента: Unicode NFC и пробелы. Все ссылки на повторные вхождения остаются в базе. Частота считается по уникальным фрагментам, а не по числу одинаковых копий PDF. Алгоритмы PDF.js и Poppler могут разбивать вёрстку по-разному, поэтому количество фрагментов может отличаться от прежней серверной версии.

Небольшой редакционный словарь содержит явные соответствия форм и общеупотребительные переводы. Даже они помечены для проверки в конкретном контексте. Остальные токены сохраняются как кандидаты без выдуманного перевода, грамматики или леммы; неоднозначные слова не удаляются. Кандидаты могут включать имена и служебные слова. Полноценного морфологического анализатора пока нет. Словарную статью можно отредактировать и отметить как проверенную.

## Практика и повторение

Есть DE→RU, RU→DE, карточки, ввод слова, пропуски, восстановление предложения/фрагмента и пропуск в грамматическом контексте. Последний режим не выполняет синтаксический анализ и не заменяет отдельный грамматический курс.

Контексты заданий берутся только из версии с меткой **«без ответов»**. Явные ключи, русские аннотации и слишком длинные фрагменты исключаются. Правильная версия файла выбирается при импорте: приложение не может гарантированно обнаружить все ответы в неверно помеченном PDF. Версия с ответами остаётся доступной в справочнике. Во время задания UI не получает эталон до отправки ответа; карточки раскрываются явно. Это учебный режим: данные в собственном браузере можно изучить через инструменты разработчика.

Сравнение ответов учитывает регистр, Unicode, пробелы и конечную пунктуацию; умлауты и `ß` не приравниваются другим буквам. Для DE→RU принимается одно из значений, разделённых `;`. Автоматической семантической оценки свободных синонимов и порядка слов нет.

SM-2 сохраняет расписание и попытку одной транзакцией. Карточки используют самооценки 1/3/4/5; упражнения — 4 за успех и 1 за ошибку. Интервалы: 1 день, 6 дней, затем предыдущий интервал × ease; ошибка сбрасывает серию и назначает повтор через день. Двойная отправка не создаёт вторую попытку. «Изучено» — минимум три успешных повтора подряд. Цель — 10 ответов в день, день статистики считается по UTC.

SpeechSynthesis использует доступные немецкие голоса устройства; качество и офлайн-поддержка зависят от системы. Распознавание речи включается по действию пользователя и разрешению микрофона, поддерживается не во всех браузерах и может обращаться к внешнему сервису браузера. Ручной ввод доступен всегда.

## Хранение и офлайн

PDF-тренажёр использует отдельную IndexedDB `deutschtrainer-pdf-v1`. Существующие занятия Passiv, аудирование и разговорная практика сохранены; их данные остаются в прежней IndexedDB `deutschtrainer`, и их отдельный экспорт находится в «Данные и настройки».

JSON/CSV PDF-тренажёра содержат **историю и расписания**, без PDF и редакторских правок словаря. Импорт объединяет историю по UUID и заменяет расписание совпадающих слов; перед импортом экспортируйте текущие данные. Неверная копия отклоняется целиком. Для переноса сначала импортируйте исходные PDF. Формат прогресса совместим с предыдущей серверной версией для существующих идентификаторов слов; неизвестные слова требуют предварительного импорта.

После первой полной загрузки production-сайта service worker сохраняет интерфейс, PDF.js worker, словари кодировок и шрифты. После завершения установки можно читать ранее импортированную библиотеку, практиковаться и импортировать текстовые PDF офлайн. При первом открытии без сети сайт ещё не установлен. Статические файлы сохраняются в отдельном кэше установки; PDF и прогресс остаются в IndexedDB и не попадают в общий кэш. Голосовые функции могут требовать сети.

## Структура

```text
src/lib/pdf/extraction.ts  браузерный PDF.js, страницы и нормализация
src/lib/pdf/store.ts       IndexedDB, дедупликация, задания, SM-2
src/lib/pdf/transfer.ts    JSON/CSV и валидация
src/lib/pdf/local-api.ts   локальный адаптер интерфейса, без HTTP API
src/lib/pdf/lexicon.ts     небольшой редакционный словарь
src/components/PdfTrainer.tsx
scripts/                  сборка, офлайн-манифест и публикация Pages
e2e/                      браузерные проверки desktop/mobile
```

`server/`, Docker и SQLite сохранены как предыдущий альтернативный вариант, но **не используются опубликованной браузерной версией**. Его отдельные тесты: `npm run test:backend` (нужен `pdftotext` из Poppler). Старый каталог `data/` не удаляется и не публикуется. Историческая инструкция: [docs/deployment.md](docs/deployment.md).
