> Предыдущий серверный вариант. Для выбранной браузерной версии на GitHub Pages VPS, Docker и эти команды не нужны. Актуальная инструкция — в README. Текущий React-клиент использует IndexedDB и не обращается к SQLite API.

# Публикация Deutsch B2 Beruf Trainer

Нужен VPS с Docker Compose, доменное имя и постоянный диск. Создание платного сервера и регистрация домена не выполняются автоматически. Внешняя публикация считается завершённой только после запуска на выбранном сервере и проверки его HTTPS-адреса.

## Что подготовлено

- `Dockerfile`: Node 24, Poppler, тесты и сборка React; runtime работает от пользователя `node`.
- `server/production.mjs` / `npm start`: один сервер для собранного интерфейса и API. Vite на production не нужен.
- `compose.yaml`: приложение, постоянный том SQLite/PDF, Caddy для HTTPS.
- Вход через HTTP Basic Auth. Логин и пароль задаются только в защищённых настройках хостинга или локальном `.env`; сервер не запустится без них. Пароль минимум 16 символов. Не вводите пароль в чат и не коммитьте `.env`.

## VPS с Docker Compose

1. Настройте DNS A (и AAAA, если используется IPv6) вашего домена на адрес VPS. Откройте входящие TCP 80/443 и UDP 443 для HTTPS/HTTP3. Доступ к SSH должен уже работать.
2. Скопируйте исходники на VPS, не включая `node_modules`, `.git`, `.env`, `dist` и `data`. Новые файлы должны присутствовать на сервере; старый GitHub `main` сам по себе их не содержит, пока изменения не отправлены в репозиторий.
3. В каталоге приложения выполните:

```sh
cp .env.example .env
chmod 600 .env
# В локальном редакторе заполните APP_DOMAIN, TRAINER_AUTH_USER и TRAINER_AUTH_PASSWORD.
# Не вставляйте секреты прямо в команду, которая сохраняется в истории shell.
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=60 trainer https
```

4. Откройте `https://ВАШ-ДОМЕН`. Браузер запросит логин и пароль. `/api/health` возвращает только минимальный статус без входа — для health checks. PDF, словарь, прогресс и интерфейс требуют входа.
5. Проверьте загрузку PDF, словарь, одно упражнение и сохранение после `docker compose restart trainer`. Другой браузер с тем же входом использует ту же SQLite; это личная установка, не система отдельных аккаунтов.

Caddy получает TLS-сертификат автоматически, когда домен указывает на сервер и доступны порты. Не используйте Basic Auth через открытый HTTP. Compose не публикует порт приложения напрямую: доступ извне идёт через Caddy.

## Перенос уже импортированных PDF и SQLite

Docker image намеренно не содержит личных PDF, SQLite и секретов. Если перенос данных не нужен, просто импортируйте оба PDF через интерфейс.

Для переноса всей библиотеки подготовьте согласованную копию `data/`: остановите процесс, который использует исходную SQLite, и скопируйте весь каталог. При работающей БД используйте SQLite backup API, а не копирование одного файла.

Скопируйте подготовленный каталог на VPS как `data-transfer/` рядом с Compose, затем:

```sh
docker compose stop trainer
# Архив или резервная копия существующего тома необходимы перед заменой старой библиотеки.
docker compose cp data-transfer/. trainer:/app/data/
docker compose run --rm --no-deps --user root trainer chown -R node:node /app/data
docker compose up -d trainer
```

Не заменяйте существующую библиотеку без резервной копии. Файлы `data-transfer/` не должны попадать в Git или Docker image. После переноса проверьте, что отображаются обе версии PDF и прежние результаты.

## Обновление и резервные копии

Перед обновлением остановите приложение и сделайте backup постоянного тома либо используйте SQLite-aware backup. Обновите исходники и выполните `docker compose up -d --build`; именованный том сохраняется. **Не выполняйте `docker compose down -v`**, если хотите сохранить библиотеку и прогресс.

Экспорт JSON/CSV из интерфейса содержит только расписания и историю. Для полной копии нужны SQLite и исходные PDF из постоянного тома. У legacy-разделов своя IndexedDB в браузере; их прогресс переносится отдельным экспортом.

## Другой Docker-хостинг

Хостинг должен поддерживать постоянный диск и **один экземпляр** приложения для этой SQLite. Build: корневой `Dockerfile`. Порт: `PORT` (по умолчанию 8080). Mount постоянного диска: `/app/data`. Переменные `TRAINER_AUTH_USER`, `TRAINER_AUTH_PASSWORD` задаются через secure environment settings. HTTPS должен завершаться на доверенном прокси провайдера. Health path: `/api/health`. Без постоянного диска данные могут пропасть после перезапуска.

## Запуск без Docker

На сервере с Node 24+ и `pdftotext`:

```sh
npm ci
npm test
npm run build
# Задайте TRAINER_AUTH_USER и TRAINER_AUTH_PASSWORD безопасно через менеджер процессов.
# При работе за локальным reverse proxy задайте HOST=127.0.0.1.
npm start
```

Используйте процесс-менеджер и HTTPS reverse proxy. Нельзя запускать `npm run dev` как публичный production-сервис. GitHub Pages не может выполнять этот backend.
